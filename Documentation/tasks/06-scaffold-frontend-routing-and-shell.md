# Issue #6: Scaffold frontend routing and shell for the four screens

## What was done

Turned the frontend from the default Vite + React + TypeScript template (still the unmodified counter demo) into the real app shell: four top-level routes — Guest ordering, Kitchen display, Hall status board, Management/admin — each laid out per `Documentation/Design/README.md`, with the design system's colors/fonts/spacing/radii/shadows wired up as reusable CSS tokens. The four screens deliberately don't share nav chrome (they're four separate physical devices per CLAUDE.md — guest tablet, kitchen wall monitor, hall board, office computer). Per the user's explicit request, also added a light/dark theme toggle — not something the design doc calls for (it describes fixed per-screen palettes), applied uniformly to all four screens as one shared `localStorage` preference.

No real feature content yet — later tickets build out what lives inside each shell; issues #13–#16 specifically replace the admin sub-sections' `ComingSoonView` placeholders with real content.

## Why each dependency

| Dependency | Purpose |
|---|---|
| `react-router` (v8.4.0) | Routing. The issue was written assuming the old `react-router-dom` split, but v8 (released June 2026) removed that package entirely — confirmed on npm (`react-router-dom` is frozen at 7.18.4, no v8 exists) and by inspecting the installed package's actual type declarations, since an earlier web search summarized a different version's import shape (it claimed `BrowserRouter` moved to a `react-router/dom` submodule; the real v8.4.0 exports everything, including `BrowserRouter`, from the root `react-router` package — `react-router/dom` only has `RouterProvider`/`HydratedRouter`/RSC-only exports). Always verify against the actual installed package, not a changelog summary. |

## The other files

- **`src/styles/tokens.css`** — the design tokens, structured as semantic/theme-aware CSS custom properties (`--bg`, `--text`, `--accent-forest`, etc.) rather than raw color names, so the light/dark toggle can redefine them per theme instead of per screen. The dark accent values aren't invented — they're the README's own documented "on-dark" tints (Forest/Amber/Clay), just applied bidirectionally.
- **`src/theme/theme-context.ts`, `ThemeProvider.tsx`, `ThemeToggle.tsx`** — one shared `localStorage` key across all four screens. `useTheme`/`ThemeContext` live in a separate file from the `ThemeProvider` component because ESLint's `react-refresh/only-export-components` rule (a real lint failure hit during this ticket) requires a file to export either only components or only non-components, not both. Each screen mounts its own `<ThemeProvider defaultTheme="light|dark">` rather than one wrapping the whole router — simpler than computing a route-based default at a single top-level mount, and the "shared preference" behavior still holds since every instance reads/writes the same key.
- **`src/screens/{guest,kitchen,hall,admin}/`** — one shell component + stylesheet per screen, matching each screen's layout description in the design doc (guest: centered device frame; kitchen: 3-column board; hall: 2-panel board; admin: sidebar + content pane). `admin/AdminScreen.tsx` renders `<Outlet/>` for 7 nested routes (`orders`/`history`/`meals`/`materials`/`tables`/`staff`/`settings`, matching the prototype's own nav array exactly), each currently rendering the shared `admin/views/ComingSoonView.tsx` placeholder.
- **`src/screens/home/HomeScreen.tsx`** — a dev-only landing page at `/` linking to the four screens; not a production route, just a QA convenience for this ticket.
- Removed: `App.css`, `src/assets/{hero,react,vite}.*`, `public/icons.svg` — all Vite-template demo-only cruft. `index.html`'s `<title>` and Google Fonts `<link>`s were added; `index.css` was trimmed to a plain reset (the leftover Vite-template placeholder theme/dark-mode block is gone, replaced by the real token system).
- **`frontend/README.md`** — rewritten from 100% generic Vite boilerplate to real setup/run instructions and a route table.
